## 评分重点说明

### Part 1 评分重点

- **工具描述质量**：这是 LLM 决策的唯一依据，描述不清晰会导致误调用
- **Schema 格式正确性**：missing required 字段会导致 LLM 调用失败
- **测试完整性**：必须有完整的测试输出，证明工具能正常工作

### Part 2 评分重点

- **ReAct 循环正确性**：退出条件、工具结果反馈是关键
- **System Prompt 设计**：必须强调 Thought-Action-Observation 格式
- **执行历史记录**：这是调试和审计的基础

### Part 3 评分重点

- **规划逻辑正确性**：生成的规划步骤顺序必须合理
- **Few-shot 质量**：示例必须展示正确的依赖关系
- **对比实验**：必须有数据支撑，证明规划的价值

## 典型错误示例

### 错误 1：ReAct 循环缺少退出条件

```python
# 错误示例
while True:
    response = llm_call(...)
    if response.tool_calls:
        execute_tools(...)
    else:
        return response.content
# 问题：如果 LLM 持续调用工具，会无限循环

# 正确做法
for iteration in range(max_iterations):
    ...
```

### 错误 2：工具 Schema 缺少 required

```python
# 错误示例
"parameters": {
    "type": "object",
    "properties": {
        "text": {"type": "string"}
    }
}
# 问题：LLM 不知道 text 是必需的

# 正确做法
"parameters": {
    "type": "object",
    "properties": {
        "text": {"type": "string"}
    },
    "required": ["text"]
}
```

### 错误 3：工具结果未反馈给 LLM

```python
# 错误示例
result = execute_tool(tool_name, tool_args)
# 问题：结果没有反馈给 LLM，LLM 无法继续推理

# 正确做法
result = execute_tool(tool_name, tool_args)
messages.append({
    "role": "tool",
    "content": json.dumps(result)
})
```
