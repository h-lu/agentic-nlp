# Week 06 评分标准

## 评分概览

| 类别 | 分值 | 说明 |
|------|------|------|
| **基础练习** | 60 分 | 三角色架构、检索 Agent、人工审核 |
| **进阶练习** | 25 分 | 并行执行、决策仲裁 |
| **挑战练习** | 15 分 | 自适应检索策略 |
| **总分** | 100 分 | 满分 100 分，挑战题可超过 |

## 基础练习（60 分）

### Part 1：规划者-执行者-审核者架构（25 分）

| 评分项 | 分值 | 评分标准 |
|--------|------|---------|
| **规划者 Agent** | 8 分 | - 3 分：create_plan 正确实现，生成结构化计划<br>- 2 分：使用 Few-shot 让 LLM 学会规划<br>- 2 分：revise_plan 正确实现<br>- 1 分：计划格式清晰（步骤、工具、依赖） |
| **执行者 Agent** | 8 分 | - 3 分：execute_plan 正确按顺序执行子任务<br>- 2 分：工具调用正确，参数传递无误<br>- 2 分：记录每步的执行结果<br>- 1 分：有基本的错误处理 |
| **审核者 Agent** | 9 分 | - 3 分：review_result 正确实现<br>- 2 分：检查点完整（完成度、一致性、错误）<br>- 2 分：能给出合理的修订建议<br>- 2 分：status 判断准确 |

**常见扣分项**：
- [-2 分] 规划者缺少 Few-shot 示例
- [-2 分] 执行者没有记录执行结果
- [-1 分] 工具调用失败没有处理
- [-2 分] 审核者检查点不完整
- [-1 分] 计划格式混乱，难以解析

**测试输出要求**：
- 必须展示完整的执行流程（规划→执行→审核）
- 如果触发修订，展示修订前后的计划对比
- 输出每个 Agent 的决策和理由

### Part 2：检索 Agent（Agentic RAG）（20 分）

| 评分项 | 分值 | 评分标准 |
|--------|------|---------|
| **检索策略决策** | 8 分 | - 3 分：_decide_strategy 正确实现<br>- 3 分：能根据查询特征选择合适策略<br>- 2 分：reasoning 字段清晰说明选择原因 |
| **结果评估** | 5 分 | - 3 分：_assess_results 正确实现<br>- 2 分：能识别检索结果是否足够 |
| **工作流集成** | 7 分 | - 3 分：MultiAgentWorkflow 正确集成检索 Agent<br>- 2 分：执行者能正确调用检索 Agent<br>- 2 分：检索结果正确传递给后续步骤 |

**常见扣分项**：
- [-2 分] 策略决策是硬编码（如所有查询都用向量检索）
- [-2 分] 没有评估检索结果质量
- [-1 分] reasoning 字段缺失或过于简单
- [-2 分] 检索 Agent 未集成到工作流

**测试输出要求**：
- 展示至少 3 种不同类型查询的策略选择（精确匹配、语义相似、复杂查询）
- 每种查询要输出选择的策略和理由
- 对比传统 RAG 和 Agentic RAG 的差异

## 扣分项汇总

### 严重问题（-2 分至 -5 分）

## 评分流程

1. **运行测试**（-5 分如果无法运行）
   - 尝试运行所有代码
   - 检查是否有明显的运行时错误

2. **检查基础练习**（60 分）
   - 检查三角色架构实现
   - 检查检索 Agent 实现
   - 检查人工审核实现

3. **检查进阶练习**（25 分，如果完成）
   - 检查并行执行实现
   - 检查仲裁者实现

4. **检查挑战练习**（15 分，如果完成）
   - 检查自适应检索实现

5. **检查报告质量**（通用）
   - 检查完整性
   - 检查数据支撑
   - 检查分析深度

6. **评分汇总**
   - 计算总分
   - 记录扣分项
   - 给出反馈建议

## 评分重点说明

### Part 1 评分重点

- **规划者 Few-shot 质量**：示例必须展示正确的规划逻辑
- **执行者状态管理**：执行结果必须清晰记录，便于审核
- **审核者检查点**：必须检查完成度、一致性、错误

### Part 2 评分重点

- **策略决策的智能性**：不是硬编码规则，而是 LLM 根据查询特征决策
- **检索结果评估**：必须有评估，不是所有检索都接受
- **工作流集成**：检索 Agent 必须正确集成到工作流中

### Part 3 评分重点

- **审核点的合理性**：审核点必须有实际价值，不是走过场
- **反馈处理**：拒绝后必须能修订，不是简单中止
- **用户体验**：审核信息必须清晰，包含足够上下文

## 典型错误示例

### 错误 1：直接修改原始 plan

```python
# 错误示例
for subtask in plan["subtasks"]:
    result = execute_tool(...)
    subtask["result"] = result  # 修改原始 plan
# 问题：如果需要修订，原始 plan 已丢失

# 正确做法
execution_results = []
for subtask in plan["subtasks"]:
    result = execute_tool(...)
    execution_results.append({
        "step": subtask["step"],
        "result": result
    })
```

### 错误 2：硬编码检索策略

```python
# 错误示例
def _decide_strategy(self, query):
    return {"method": "vector"}  # 所有查询都用向量检索
# 问题：没有体现 Agentic RAG 的智能性

# 正确做法
def _decide_strategy(self, query):
    prompt = f"""分析查询，决定最佳检索策略。
    查询：{query}
    输出 JSON 决策..."""
    # 让 LLM 根据查询特征决策
```

### 错误 3：人工审核后没有修订

```python
# 错误示例
approved = input("批准？(y/n): ")
if not approved:
    print("已拒绝")
    return  # 直接结束
# 问题：拒绝后没有修订机制

# 正确做法
if not approved:
    feedback = input("修改建议: ")
    revised_plan = planner.revise_plan(plan, feedback)
    # 继续执行修订后的计划
```
